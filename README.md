## 工夫した点

- **レスポンシブに対応しました。** 仕様書では1200px固定でよいとされていましたが、`width` を `max-width` に変えるところから始め、`@media` で 1024 / 768 / 480 の3段階を用意しました。768px以下ではCOURSEの写真と文章を縦に積み、フォームのラベルを入力欄の上に移しています。

- **COURSEの2行目を `flex-direction: row-reverse` で左右反転させました。** HTMLは3行とも同じ順番（画像→文章）で書いてあり、CSS1行だけで見た目が入れ替わります。読み上げ順を崩さずに済みます。縦積みになる768px以下では `column` に上書きして揃えました。

- **`<br>` を狭い画面で `display: none` にしました。** 1200px幅に合わせて入れた改行位置が、スマホでは不自然になるためです。HTMLを書き換えずCSSだけで処理しました。

- **完成見本の画像から色を実際に拾って確認しました。** 見た目では全部同じに見えましたが、ABOUTとNEWSの見出しだけが黄色で、COURSE・Access・CONTACTは黒でした。

- **Googleマップの埋め込みコードから、見た目の指定だけCSSに移しました。** `width` `height` `style="border:0"` を外し、機能の属性（`allowfullscreen` `loading` `referrerpolicy`）だけHTMLに残しています。インラインの `style` はクラスより優先されるため、HTMLに残すとCSSから変更できなくなるためです。

## 難しかった点

- **「CSSが効かない」の原因が、書き間違いによる構文エラーだったこと。** 1か所間違えると、そこから下が全部読まれなくなると知りませんでした。保存時に自動整形する Prettier を入れて、整形されなければ壊れている、と分かるようにしました。

- **`display` の違い。** `<a>` は inline なので、`display: inline-block` を書かないと `width` も `height` も効きません。ここで一番時間を使いました。

- **`flex-direction: column` にすると `justify-content` が縦方向になること。** 主軸の考え方が最初つかめませんでした。
